# Two-row header

Global header in header group. Header section selects single-row (existing) or two-row (new static composition); one root controller and one search form. Dedicated composition block owns grid/action gaps and padding, compact/mobile fallback, fixed role slots; leaf blocks own content/data. Reuse native menu/drawer, localization, account and cart handlers; no second controller or duplicate search.
Desktop: logo/search/actions + menu/localization. Compact (<1400): hamburger/logo/actions + full-width search, menu drawer. Mobile (<768): 20px action icons and 44px form; tablet uses 24px icons/48px form. Padding controls follow desktop/mobile inheritance; compact layout has its own row spacing contract.
Search extends native GET form with a product-type filter backed by configured category blocks, qualified Shopify search query, separated accessible label/placeholder, and mobile category label. No fabricated collections. Navigation uses dedicated Shopify Torvex menu; unresolved catalog targets remain editable. Location is an editable URL, no store-locator application.
QA: schema upload, search submit/escape handling, keyboard, menu/cart/localization/account, sticky and editor reload; widths375/767/768/1149/1150/1920. Brand values stay in header-group JSON. Original one-row behavior preserved.

## Top/Bottom refinement (2026-10-12)

This supersedes the earlier 1400px compact breakpoint and combined two-row block.

- Section owns the sticky root and fixed sibling Top (`header-two-row`) and Bottom (`header-bottom`) slots. Top owns logo/search/location/account/cart; Bottom has a curated dynamic allow-list of Menu and Localization. Bottom children can be added, hidden, removed and reordered. No app slot. Shopify Theme Blocks cannot enforce a per-type child cap; the intended preset is one Menu and one Localization. The first Menu supplies the mobile drawer; extra Menu blocks remain desktop navigation.
- Reference: Marlow theme 192252936491 was inspected read-only in Theme Editor. Its Bottom separates Gap, Bottom separator and Padding from Menu content. Torvex uses these controls plus Menu items per scroll (1/2/3).
- Desktop navigation remains visible at >=992px. A single-line scroll viewport measures its contents; controls appear only on overflow, disable at the ends and advance by actual item offsets. Keyboard focus scrolls an offscreen top-level item into view. Submenus escape the scroller using fixed geometry relative to the actual sticky containing block.
- Localization panels clamp to the current iframe/window width and available height. Category selection reuses component-overlay for desktop popup/mobile bottom sheet, focus trapping, Escape, backdrop, scroll lock and the existing radius tokens. It stores the selected product type in a hidden field; there is no native select.
- Header input opens the existing Search overlay, transfers the query, focuses its input and uses its predictive search renderer. Continued typing synchronizes the visible header value. Abort/debounce and category-qualified View all/submit are handled by that existing controller.
- Scheme, typography and artwork remain settings/assets; no Custom CSS or template-specific CSS asset was added.
